## 应用选择与身份契约

侧栏props为 `currentRobot`、`robotOptions`、`robotListStatus`，事件包括 `navigate(menuKey)`、`robot-change(id)`、`retry-robots()`、`robot-removed(id)`、`robot-created(data)`。当前应用展示对象只含 `id/name/avatar`；选项包含 `id/name/avatar/intro/robotKey/applicationType`，其中密钥仅供选择校验，不写入DOM。选择器props为 `open/value/options/status`，通过 `update:open/change/retry/removed/created` 事件通知上层；不自行请求列表或修改当前应用真值。

卡片按 `applicationType` 显示“聊天机器人”或“智能体”。两类应用均保留拖拽排序、复制及按原权限删除；导出仅对类型0开放。新增机器人沿原流程，“新增 Agent”仍为占位提示，本次不接入智能体创建或导出。

## 机器人与URL

应用列表与详情使用已有 `@/api/robot` 封装：

| 调用 | 用途 |
| --- | --- |
| `getRobotList({ filter_claw: false })` | 一次获取完整列表，严格保留 `application_type` 为0或2的项，排除工作流并保持接口顺序；无分页 |
| `getRobotInfo({ id })` | 获取当前详情，核对非空归一化ID、存在且精确匹配的 `robot_key`，以及类型0或2 |

类型兼容数字与数字字符串，空值、空白、布尔值和未知类型不会被转成类型0误收。公共API默认参数保持原样，其他列表调用不受影响。

URL中的 `id`、`robot_key` 是当前机器人标识来源；切换选项时，从真实列表取得成对标识写入URL。重复参数取首项并转字符串，缺失值按空处理，不将ID限定为整数。

- 进入布局先 `reset()`，再加载列表；独立监听归一化的ID/key读取详情，列表失败不阻挡显式目标详情。
- 两个标识都无值且列表ready时，检查筛选后首项的完整ID/key（可以是机器人或智能体），再用 `router.replace` 补URL。首项标识坏只提示无效应用，不跳过改选其他项；空列表不会自动创建智能体。
- 仅缺一个标识、详情标识不匹配或类型不属于0/2时提示无效应用，不自动换应用。列表空/失败及详情失败分别局部提示并提供重试，页面占位继续显示。
- 切菜单只保留ID/key；选择任意类型均进入 `/customer-service/chat` 并清除旧业务query，不跳转Clawbot。URL生效前不主动更改当前详情或本地选中状态；同一应用换菜单不重拉详情。
- 卸载布局调用 `reset()`；列表与详情各自的请求序号使被替代或重置后的旧响应失效，不取消其他模块请求。

## 客服Store契约

导出 `useCustomerServiceStore`，Pinia ID为 `customer-service`。公开以下5项状态、列表/详情/重置方法及配置窄动作，无另一份独立选中ID/key，不持久化；独立于 `src/stores/modules/` 下的 `robot.js`、`chat.js`、`clawbot.js`、`clawbot-chat.js` 等既有Store文件。

| 状态 | 值与含义 |
| --- | --- |
| `robots` | 类型0/2的应用列表，初始/重置为 `[]` |
| `robot` | 已校验的当前详情，初始/重置及新详情读取前为 `null` |
| `robotListStatus` | `idle` / `loading` / `ready` / `error`；空列表也为ready |
| `robotStatus` | `empty` / `loading` / `ready` / `error`；两标识均无值时为empty |
| `robotError` | 正常为 `''`；标识残缺/不匹配/类型错误为 `invalid_robot`，详情请求失败为 `error_robot` |

| 方法 | 返回方式 |
| --- | --- |
| `loadRobots()` | Promise：成功返回过滤后的数组（含空数组），失败或结果过期返回 `null`；不改变详情状态 |
| `loadRobot({ id, robotKey })` | Promise：成功返回详情；无参、残缺、失败或结果过期返回 `null`，通过状态区分原因 |
| `reset()` | 同步清空5项状态并使在途结果失效，无返回值 |

配置窄动作包括 `mergeCurrentRobotInfo`、`refreshCurrentRobot`、`saveRobotSettings`，详见 `chat/README.md`。welcome配置回填和详情刷新必须保持原应用ID、key和类型一致，不能在0与2之间转换；模型/人设保存显式传当前应用的真实类型。

布局用 `storeToRefs` 读取状态。后续页面需要基础机器人信息时可读取此Store；URL监听和导航仍由布局负责。
